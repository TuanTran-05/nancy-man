# Variables rollback failure

`ROLLBACK_FAILED` is a stop condition. The agent retains the encrypted snapshot and
creates a Critical incident; later applies for that exact application are blocked.
Do not delete evidence or retry by changing the browser request.

1. Disable the relevant variables write flags and preserve the current release.
2. Open the linked Critical incident using only application/change/run/snapshot IDs,
   failed action/check IDs, timestamps, and reason codes.
3. Remediate the host or service through the approved maintenance procedure. Do not
   paste source paths, variable names, values, command output, or file bytes into the
   incident.
4. Restore the source/release and verify manifest-declared health evidence.
5. An owner submits the exact application ID, resolved incident ID, value-free
   remediation summary, and a fresh one-use `accounts_write` password+TOTP grant.
   The API and agent both verify the block identity and health evidence.
6. Confirm the block is cleared, then rerun the rollback-failure drill before any
   write flag is re-enabled.

There is no generic unblock endpoint and no force apply path.
